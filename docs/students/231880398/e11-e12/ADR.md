# ADR：E11–E12 个人集成与真实项目适配

状态：已实施（2026-11-16）

## 1. 在 PR #14 基线上做个人实验

问题：组内 `main` 还没有 E11–E12 代码，PR #14 仍在评审。

选择：从 `refs/pull/14/head`（`381a46b`）建立 `student/231880398/e11-e12`，完成个人运行和文档；不代替组长合并 PR #14。

代价：PR #14 合并后，个人分支需要 rebase/merge 到最新 `main` 并重跑 CI。这样可以先验证个人交付，又不阻塞组长的合并顺序。

## 2. 外层版本与 E8–E10 内层报告分离

问题：E8–E10 报告已经有 `e8e10-1` 字段，E11–E12 需要统一 envelope。

选择：外层使用 `e11e12-1`，内层 `data` 保留 `e8e10-1`；外层 `commit` 和内部 `data.commit` 都校验，避免旧报告被新任务消费。

代价：报告多一层嵌套；反序列化时必须同时检查两层版本和 commit。

## 3. 真实项目采用课程 fixture 的独立适配

问题：课堂提供的 `fixtures/md-rd` 是单源 Make 项目，不满足当前双源接口；直接复用 397 的真实项目证据不符合个人独立交付要求。

选择：由 231880398 复制 fixture，补 `helper.c`、双目标 Makefile、`extra.h` 和 `Dockerfile.broken`，独立建立 C0/C1；C1 让 `helper.c` 引入 `config.h`，而 `helper.o` 规则漏写它。源码快照提交到 `labs/e11e12/projects/231880398-real/`。

代价：这仍是教学规模项目，不是外部生产仓库；若课堂要求外部项目，需要教师/助教确认后另建数据集。

## 4. API 只绑定回环并保留负向契约

问题：联调需要可复现的 idempotency、路径安全和重启语义。

选择：服务器默认绑定 `127.0.0.1`；同键同输入复用 job_id，同键不同输入返回 409；文件路径拒绝 `.git`、越界路径和不存在 job；重启时把 `QUEUED`/`RUNNING` 标为 `FAILED / SERVER_RESTARTED`，保留 `SUCCEEDED`。

代价：跨主机 A/B 交换需要 SSH 转发，不能直接公网暴露；本轮未做跨主机交换。

## 5. 保留第一次真实项目失败

问题：第一次 E12 真实项目因项目缺少 `Dockerfile.broken` 失败。

选择：不删除失败输出；补充文件后重建 C0/C1 并保留第二次成功输出，报告中同时记录失败 job、原因和修复。

代价：证据目录多一份失败运行，但能复现问题和修复过程。
