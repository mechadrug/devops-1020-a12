# 决策记录：条件编译参数导致依赖变化

- 背景：A 组 EChecker 需要证明历史依赖图何时可复用，以及配置变化何时必须刷新。
- 选择：在 `config.h` 中放置 `#ifdef MODE` 控制的 `#include "extra.h"`，只改变 Makefile 的 `CFLAGS`，从 `-O0` 到 `-O0 -DMODE=1`。这样源文件及头文件文本不变，新增依赖可明确归因于编译参数。
- 独立预期：旧图无 `main.o→extra.h`；启用 MODE 后 GCC 全量扫描新增这条实际边和 MISSING 发现。配置签名变化应使旧图失效，两个目标刷新；增量和全量结果一致。
- 代价：当前教学实现采用全目标保守刷新，正确性优先，未优化成仅刷新受影响目标。5 次本地测量显示该场景增量中位数略高于全量，不作性能提升主张。
- 验证：`StudentA231880397` 的 E9/E10 测试、本机与课程服务器各 5 次结果，以及服务器真实 BuildChecker 重检。适用范围仅为课程支持的显式 C/Make 样例。
