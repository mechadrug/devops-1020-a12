# ADR：用独立请求与传输、重启契约验证集成边界

作者：王备中 231880138。日期：2026-11-16。状态：已实测。

背景：公共 PR14 已实现动态全量图接入全局缓存、版本化报告、哈希产物和单 worker API。需要验证本人不同目标提交，并补足现有契约测试对真实内容篡改和持久任务恢复的覆盖。

选择：个人目标只改变 helper 函数体，以固定预期证明该配置下两目标复用；用基线/目标真实全量作对照。新增同长度有效 JSON 篡改负例，避免只测试错误常量摘要；新增持久状态恢复测试，覆盖 QUEUED、RUNNING 与已完成任务。实际 API 进一步重启验证完成任务的身份及幂等结果保留。

数据与环境：自己的克隆、镜像、work 和回环端口 8082。沿用组内有来源的 fixture 适配数据做本人独立 E12，保留其贡献归属；课堂生成数据另列，不制造外部真实项目声明。原始图、请求、封装和全部产物 SHA 均保留。

代价：当前全局预处理 key 对 include 变化会刷新所有目标；本次证明函数体变化复用，没有实现按影响范围选择性刷新。单服务编排和受限 C/Make 配置不能代表生产多服务架构。Docker socket 与候选回放按课程可信环境使用；API 只在宿主回环地址暴露。复杂项目映射和真正跨组跨机操作需另做验证。

验证：13 项契约测试、两次 E11-A、个人与组内数据 E12、API 幂等/409/下载哈希/重启、STALE_REPORT 与 ARTIFACT_HASH_MISMATCH 负例。完整命令及路径见个人报告。
