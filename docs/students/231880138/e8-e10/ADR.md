# ADR：用独立边集检查传递依赖的缓存行为

状态：已验证。作者：王备中 231880138。日期：2026-11-10。

背景：课程参考实现以预处理行、源文件集合、配方和配置构造 key，相同 key 复用 actual，每次重读 declared 并重算 findings；任一 key 差异保守刷新两目标。胡凌岳已覆盖补声明、新增 include 与增量/全量相等，本人需要增加不同的输入边界。

选择：增加“间接头文件函数体变化”“删除间接 include 并删文件”“传递声明补齐且删除 RD”三项测试。每项先写固定完整边集和 added/resolved 预期，再调用实现。E10 额外对删除场景运行五次，保存增量/全量原始 JSON，并用真实 BuildChecker 对象目标投影交叉核对。

替代方案：仅断言 passed 或 findings 数量会漏掉目标/依赖错配；仅重复手册 include 示例无法覆盖旧边应消除的情况。暂不改为按目标选择性刷新，因为这需要维护反向传递关系和更广覆盖，超出本次可验证范围。

代价与范围：全目标保守刷新使删除/配置变化的小样例未取得加速；同实现的增量与全量一致不能独自证明算法完全正确，因此保留独立预期和 strace 动态交叉检查。复杂生成头文件、隐式规则和完整论文机制仍不在支持范围内。

证据：个人报告列出的三个 unittest、13 项真实测试日志、E8 BuildChecker 基线、E10 30 行矩阵及额外五次删除场景，均绑定外层源码 68bf0fa865ec52d0e21da28e2bd8ec623265f0f5。原始输入、内部提交与日志在本人 work 归档。
